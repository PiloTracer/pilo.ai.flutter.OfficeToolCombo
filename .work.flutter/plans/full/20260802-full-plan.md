# OfficeToolCombo — master implementation plan

## 1. Summary

OfficeToolCombo ships a **desktop Flutter application** (Linux, macOS, Windows) for non-technical office staff to run five paid operational jobs without a terminal: merge Excel reports, track inventory via barcode wedge, batch-generate PDFs, monitor prices with OS notifications, and schedule dated folder backups. Milestones **F0–F6** deliver a demoable vertical slice per tool, then accessibility polish and installable release artifacts. Target users are desk-based coordinators, stock clerks, admin assistants, buyers, and office managers. Success is measured by per-tool acceptance criteria, **≥ 80% line coverage**, **≤ 80 MB** compressed Linux artifact, and **≤ 2500 ms** cold start on the reference Linux desktop. Plan-ready foundation certified **2026-08-02**.

## 4. Architecture summary

**Layers:** View → ViewModel → Domain ← Data (per doc 03 and `20260802-ARCHITECTURE_STANDARD.md`).

| Layer | Location | May depend on |
|-------|----------|---------------|
| View | `lib/features/<feature>/presentation/` | ViewModel (Riverpod), theme, l10n |
| ViewModel | `*_view_model.dart`, `@riverpod` notifiers | Domain repository interfaces |
| Domain | `lib/features/<feature>/domain/` | Pure Dart only |
| Data | `lib/features/<feature>/data/` | Domain |

**Composition root:** `lib/bootstrap.dart` → `ProviderScope` → `lib/app.dart` (`MaterialApp.router`). Shared wiring in `lib/core/di/`, routing in `lib/core/router/app_router.dart`, drift in `lib/core/storage/`.

**Feature modules:** `home`, `settings`, `report_consolidator`, `barcode_inventory`, `document_factory`, `price_monitor`, `scheduled_backup`. Cross-tool navigation via router only — no feature imports another feature's `data/` or `presentation/`.

**Error model:** Sealed `*Failure` in domain; unexpected errors logged via redacting logger; ViewModels map to six UI states (loading, empty, partial, error, offline, success).

## 5. Scope

**In scope (v1):**

- F0 skeleton: router shell, DI, theme, drift bootstrap, minimal settings, five navigable empty tool screens
- F1 report consolidator (folder of `.xlsx` → merged output + failure list)
- F2 barcode inventory (wedge input, drift persistence)
- F3 document factory (template + data sheet → PDF batch + per-row errors)
- F4 price monitor (watch, threshold, OS notification, offline badge)
- F5 scheduled backup (daily zip, dated archive name, manual run)
- F6 accessibility polish, en/es completeness, release artifacts for linux/macos/windows

**Out of scope (v1):**

- iOS, Android, Web
- Cloud upload, multi-device sync, user accounts
- HIPAA/PCI workflows, RTL locales, custom macro language
- P1 candidates: cloud backup destination, multi-template library UI, inventory CSV export, sub-daily cron

**Cut list (drop first under pressure, in order):**

1. Spanish locale completeness (ship en-only)
2. Price monitor history samples beyond latest (keep latest only)
3. Scan event retention beyond 30 days (reduce to 7)
4. Document factory progress granularity (coarser updates)
5. macOS/Windows release artifacts (ship Linux-only internal)
6. Scheduled backup (manual run only; defer cron)

## 11. Milestones

- **F0 Skeleton (no product features)** — Theme: project structure, CI, theme, router shell, drift bootstrap, minimal settings, empty tool screens. Features: FT-00, FT-06 minimal. Depends: none. Demo: a person launches on Linux/macOS/Windows, lands on home with five tool entries, navigates to empty tool screens and back; analyze+test green. Exit: router shell + settings route; drift `001_initial`; light/dark theme; en/es l10n; redacting logger; CI gate passing.
- **F1 Report consolidator** — Theme: Excel folder merge with failure list; validates `excel` early (RSK-001). Features: FT-01. Depends: F0. Demo: a person merges a sample xlsx folder into one output plus failure list. Exit: isolate merge with progress; 20+ workbook corpus spike; NFR10 profile pass.
- **F2 Barcode inventory** — Theme: wedge scanner with drift persistence. Features: FT-02. Depends: F0. Demo: a person scans barcodes; quantities persist across restart. Exit: focus policy on three OS; NFR11 p95 ≤ 200 ms; migration tests pass.
- **F3 Document factory** — Theme: template + data sheet → PDF batch. Features: FT-03. Depends: F0. Demo: a person generates PDF batch with per-row errors listed. Exit: NFR12 benchmark ≥ 50 PDFs/min; progress ≤ 1 s behind.
- **F4 Price monitor** — Theme: dio fetch, background poll, OS notifications, offline state. Features: FT-04. Depends: F0. Demo: a person adds a watch; stubbed price cross triggers notification or banner fallback; offline badge without network. Exit: NFR9 10 min default; Linux/macOS/Windows notification spike; wake/resume test (RSK-003).
- **F5 Scheduled backup** — Theme: daily zip with dated archive name. Features: FT-05. Depends: F0. Demo: a person configures daily backup and manual run produces dated zip. Exit: schedule drift ≤ 1 min; actionable destination errors on Windows long-path.
- **F6 Polish / accessibility / release** — Theme: a11y, l10n, crash reporting, release artifacts. Features: FT-07, FT-08. Depends: F1, F2, F3, F4, F5. Demo: installable release build; a11y audit clean; en/es complete; Linux artifact ≤ 80 MB. Exit: NFR4 ≥ 80% coverage; NFR3 size gate; NFR6 zero blocking a11y violations; crash reporter wired.
