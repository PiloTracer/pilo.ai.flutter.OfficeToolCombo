# OfficeToolCombo — master implementation plan

## 1. Summary

OfficeToolCombo ships a **desktop Flutter application** (Linux, macOS, Windows) for non-technical office staff to run five **buyer-ready** paid operational jobs without a terminal: merge Excel reports, track inventory via barcode wedge, batch-generate PDFs, monitor prices with OS notifications, and schedule dated folder backups. The full UI ships in **English and Spanish**; the chosen language **survives app restart**. Milestones **F0–F6** deliver a demoable vertical slice per tool (commercial bar per foundation doc 01 §4b), then accessibility polish and installable release artifacts. Target users are desk-based coordinators, stock clerks, admin assistants, buyers, and office managers. Success is measured by per-tool commercial acceptance, **100% en/es string coverage**, **≥ 80% line coverage**, **≤ 80 MB** compressed Linux artifact, and **≤ 2500 ms** cold start on the reference Linux desktop. Plan-ready foundation certified **2026-08-02**; Revision 2 pending re-approval after commercial-bar amend.

## 4. Architecture summary

**Layers:** View → ViewModel → Domain ← Data (per doc 03 and `20260802-ARCHITECTURE_STANDARD.md`).

| Layer | Location | May depend on |
|-------|----------|---------------|
| View | `lib/features/<feature>/presentation/` | ViewModel (Riverpod), theme, l10n |
| ViewModel | `*_view_model.dart`, `@riverpod` notifiers | Domain repository interfaces |
| Domain | `lib/features/<feature>/domain/` | Pure Dart only |
| Data | `lib/features/<feature>/data/` | Domain |

**Composition root:** `lib/bootstrap.dart` → `ProviderScope` → `lib/app.dart` (`MaterialApp.router`). Shared wiring in `lib/core/di/`, routing in `lib/core/router/app_router.dart`, drift in `lib/core/storage/`.

**Feature modules:** `home`, `settings`, `report_consolidator`, `barcode_inventory`, `document_factory`, `price_monitor`, `scheduled_backup`. Cross-tool navigation via router only — no feature imports another feature's `data/` or `presentation/`.

**Error model:** Sealed `*Failure` in domain; unexpected errors logged via redacting logger; ViewModels map to six UI states (loading, empty, partial, error, offline, success).

## 5. Scope

**In scope (v1):**

- F0 skeleton: router shell, DI, theme, drift bootstrap, settings with **persistent en/es locale**, five navigable empty tool screens
- F1 report consolidator (source folder + output path → merged `.xlsx` + failure list + progress)
- F2 barcode inventory (always-ready wedge focus, unknown-SKU create, drift persistence across restart)
- F3 document factory (user template + field mapping + data sheet → PDF batch + per-row errors)
- F4 price monitor (multi-watch CRUD, threshold, OS notification, offline badge)
- F5 scheduled backup (source/destination/hour UI, dated zip, manual run, last-run status)
- F6 accessibility polish, **blocking** en/es completeness, release artifacts for linux/macos/windows

**Out of scope (v1):**

- iOS, Android, Web
- Cloud upload, multi-device sync, user accounts
- HIPAA/PCI workflows, RTL locales, custom macro language
- P1 candidates: cloud backup destination, multi-template library UI, inventory CSV export, sub-daily cron

**Cut list (drop first under pressure, in order):**

1. Price monitor history samples beyond latest (keep latest only)
2. Scan event retention beyond 30 days (reduce to 7)
3. Document factory progress granularity (coarser updates)
4. macOS/Windows release artifacts (ship Linux-only internal)
5. Scheduled backup automatic cron (keep manual run + last-run status; defer unattended schedule)

**Never on the cut list:** English/Spanish completeness; locale persistence across restart; per-tool failure lists / offline badges required by commercial bar (doc 01 §4b).

## 11. Milestones

- **F0 Skeleton (no product features)** — Theme: project structure, CI, theme, router shell, drift bootstrap, settings with persistent locale, empty tool screens. Features: FT-00, FT-06 minimal. Depends: none. Demo: a person launches on Linux/macOS/Windows, sets Spanish, quits, relaunches still in Spanish; navigates five empty tools. Exit: router shell + settings; drift `001_initial`; light/dark; en/es ARB bootstrap; locale restart test; redacting logger; CI gate.
- **F1 Report consolidator** — Theme: buyer-ready Excel folder merge; validates `excel` early (RSK-001). Features: FT-01. Depends: F0. Demo: a person picks source folder + output path, merges sample corpus, sees progress and failure list. Exit: isolate merge; output path; 20+ workbook spike; NFR10 profile pass.
- **F2 Barcode inventory** — Theme: always-ready wedge scanner + unknown SKU create. Features: FT-02. Depends: F0. Demo: a person scans known and unknown barcodes; quantities persist across restart; field ready without click. Exit: focus policy on three OS; create-unknown flow; NFR11 p95 ≤ 200 ms.
- **F3 Document factory** — Theme: user template + field mapping → PDF batch. Features: FT-03. Depends: F0. Demo: a person maps placeholders to sheet columns and generates PDF batch with per-row errors. Exit: mapping persistence; NFR12 ≥ 50 PDFs/min; progress ≤ 1 s behind.
- **F4 Price monitor** — Theme: multi-watch CRUD, dio poll, OS notifications, offline. Features: FT-04. Depends: F0. Demo: a person adds/enables watches; stubbed price cross triggers notification or banner; offline badge. Exit: NFR9; notification spike; wake/resume (RSK-003).
- **F5 Scheduled backup** — Theme: schedule UI + dated zip + last-run status. Features: FT-05. Depends: F0. Demo: a person sets source/dest/hour; manual run produces dated zip; last-run visible. Exit: schedule drift ≤ 1 min; destination errors actionable; last-run status.
- **F6 Polish / accessibility / release** — Theme: a11y, **blocking** en/es, crash reporting, release artifacts. Features: FT-07, FT-08. Depends: F1–F5. Demo: release build; a11y clean; en/es 100%; ≤ 80 MB. Exit: NFR4; NFR3; NFR6; NFR13; crash reporter.
