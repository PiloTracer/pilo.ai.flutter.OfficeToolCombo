## 1. Purpose and user value

**Feature id:** FT-03 — Document factory

**Job to be done:** An admin assistant turns rows in a data spreadsheet plus a **user-owned** document template into one personalized PDF per row, without writing code or editing the app.

**User value:** The operator selects their template (logo and static layout stay in the template file), selects a data sheet, maps template placeholders to sheet column headers once, and runs a batch job. They receive PDFs on disk, a visible progress indicator for multi-minute runs, and a per-row error list for rows that could not be rendered. The mapping is saved and reused on the next run. The tool works fully offline; no network is required.

**Success signal (from doc 01 J3):** Field mapping without code; batch PDFs plus per-row errors; progress visible for runs that may take minutes.

---

## 2. Scope

### In scope

- One active document template per session: user-selected template file on disk (PDF or Word `.docx` with placeholder tokens — exact supported formats fixed at implementation; behaviour here assumes placeholders like `{{CustomerName}}` are discoverable from the template).
- User-selected data sheet: `.xlsx` with a header row and one row per output document.
- Field-mapping editor: lists each discovered placeholder and lets the operator assign a data-sheet column header; unmapped placeholders block batch start.
- Persisted mapping: saved locally with the template record and restored when the same template is selected again.
- Batch PDF generation: one output PDF per data row, written to a user-chosen output folder; filenames include a stable row identifier (row number or a mapped key column — default row number if no key column mapped).
- Per-row errors: rows that fail validation or rendering appear in an enumerated failure list with row number and human-readable reason; successful rows still produce PDFs.
- Progress UI: shows rows completed, rows failed, and rows remaining; updates at most 1 second behind actual job progress (doc 04).
- User-supplied static layout and logo: entirely defined in the template file; the app does not embed logos or layout in code.
- Offline operation: full configure-map-generate flow with local files only (NFR7, doc 02 §4).
- Bilingual UI: every user-visible string in English and Spanish per doc 01 §4b.

### Out of scope

- Cloud upload or sync of templates, data sheets, or PDFs.
- In-app template designer or WYSIWYG editor.
- Multi-template library management beyond one saved mapping per template file path (v1).
- Merging multiple data sheets in one job.
- Email delivery or print queue integration.
- Historical job replay beyond metadata retained 30 days (doc 04).
- Custom scripting, macros, or expression language in mappings.
- Password-protected or encrypted source files (treated as unreadable — surfaced as errors).

## 4. User flows

### 4.1 Happy path — first batch with new template

1. **Entry:** User taps **Document factory** on home → navigates to `/tools/document-factory`.
2. User taps **Choose template** → file picker → selects template file → app discovers placeholders and shows template name (basename only in UI).
3. User taps **Choose data sheet** → file picker → selects `.xlsx` → app reads header row and shows column count.
4. User opens **Map fields** section → for each placeholder, selects a column from dropdown → all placeholders mapped → **Save mapping** enabled.
5. User taps **Save mapping** → confirmation: en *"Mapping saved"* / es *"Mapeo guardado"*.
6. User taps **Choose output folder** → selects writable folder.
7. User taps **Generate PDFs** → job starts → progress region shows counts → on completion, success summary with output folder (basename or "Open folder" action) and zero-row failure list if all succeeded.
8. **Exit:** User taps back → returns to home; mapping remains saved for that template.

### 4.2 Return visit — saved mapping

1. User selects the same template file as a prior saved mapping.
2. App restores column assignments automatically; user may edit and re-save.
3. User selects data sheet (may differ from last run), output folder, **Generate PDFs**.

### 4.3 Partial success batch

1. During or after run, some rows fail (missing required cell, invalid value, render error).
2. User sees progress reach 100% with **partial** outcome: en *"Generated with some errors"* / es *"Generados con algunos errores"*; failure list lists each failed row with reason; successful PDFs exist on disk.

### 4.4 Abandonment

1. User navigates back to home while job is running → job continues in background until complete or app exit; on return to document factory, UI shows latest job state (running or last completed).
2. User closes app during job → on next launch, last job shows **interrupted** if not finished: en *"The last job did not finish. You can start a new batch."* / es *"El último trabajo no terminó. Puede iniciar un nuevo lote."* No automatic resume of partial PDF writes in v1.

### 4.5 Back behaviour

- App bar back control returns to home (`/`); does not cancel an in-progress job.
- Field-mapping edits before **Save mapping** are discarded if user leaves the tool without saving (prompt only if mapping editor is dirty: en *"Discard unsaved mapping changes?"* / es *"¿Descartar cambios de mapeo sin guardar?"*).

## 6. UI states

Applies to `/tools/document-factory` main surface.

### Loading

- **When:** Initial open while restoring last template paths or in-flight job metadata from local store; after **Generate PDFs** until first progress tick; while reading template placeholders or sheet headers after file selection.
- **User sees:** Skeleton placeholders for template/data rows OR spinner with en *"Loading…"* / es *"Cargando…"*; primary buttons disabled except back.
- **User can:** Return to home.

### Empty

- **When:** No template and no data sheet selected; no prior saved job on first visit.
- **User sees:** Intro text; empty selectors with en *"No template selected"* / es *"Ninguna plantilla seleccionada"* and en *"No data sheet selected"* / es *"Ninguna hoja de datos seleccionada"*; **Generate PDFs** disabled; mapping section hidden or collapsed with en *"Select a template and data sheet to map fields"* / es *"Seleccione plantilla y hoja de datos para mapear campos"*.
- **User sees (distinct from error):** Inbox-style icon, no error colour; no retry button.

### Partial

- **When:** Batch finished with ≥1 successful PDF and ≥1 failed row; OR file selection succeeded but placeholder discovery found zero placeholders (configuration incomplete — mapping empty state).
- **User sees (batch partial):** Title en *"Generated with some errors"* / es *"Generados con algunos errores"*; counts en *"{success} PDFs created, {failed} rows failed"* / es *"{success} PDFs creados, {failed} filas fallaron"*; scrollable failure list; **Open output folder** action if at least one PDF exists.
- **User sees (zero placeholders):** en *"No placeholders found in this template. Use a template with {{FieldName}} tokens."* / es *"No se encontraron marcadores en esta plantilla. Use marcadores {{NombreCampo}}."* — warning style, not crash.

### Error

- **When:** Unreadable template or sheet; output folder not writable; job failed entirely (0 PDFs); unexpected failure.
- **User sees:** Icon `error_outline`; title en *"Batch failed"* / es *"Lote fallido"* OR specific titles below; message with actionable text; **Try again** re-enables **Generate PDFs** without clearing selections.
- **Specific messages:**
  - Unreadable template: en *"Could not read the template file. Choose a different file."* / es *"No se pudo leer la plantilla. Elija otro archivo."*
  - Unreadable data sheet: en *"Could not read the data sheet. Choose a different .xlsx file."* / es *"No se pudo leer la hoja de datos. Elija otro archivo .xlsx."*
  - Output not writable: en *"Cannot write to the output folder. Choose a folder where you have permission to save files."* / es *"No se puede escribir en la carpeta de salida. Elija una carpeta con permiso de escritura."*
  - Generic: en *"Something went wrong during PDF generation."* / es *"Algo salió mal al generar los PDFs."*

### Offline

- **When:** No network at cold start or anytime (connectivity irrelevant to this tool).
- **User sees:** No offline badge on this tool (offline is the normal mode). Other tools unaffected. Full flow available.
- **Distinction:** Not shown as error; no "offline" banner on document factory screen.

### Success

- **When:** Batch completed; all rows rendered successfully (≥1 row).
- **User sees:** Title en *"PDFs generated"* / es *"PDFs generados"*; en *"{count} PDFs saved to {folderBasename}"* / es *"{count} PDFs guardados en {folderBasename}"*; **Open output folder** button; empty failure list hidden.
- **Boundaries:** One row → en *"1 PDF saved…"* / es *"1 PDF guardado…"*; maximum realistic batch (reference benchmark corpus, e.g. 500 rows) — progress remains visible throughout; UI stays interactive (NFR2 frame budget during progress updates).

### In-progress (sub-state of loading/success path)

- **When:** Job running.
- **User sees:** Determinate progress bar; en *"Generating PDFs… {done} of {total}"* / es *"Generando PDFs… {done} de {total}"*; failed count if any so far; **Generate PDFs** disabled; cancel not offered in v1.

## 7. Data contract

| Entity | Read / write | Source of truth | Freshness | Validation |
|--------|--------------|-----------------|-----------|------------|
| **DocumentTemplate** | R/W | drift metadata + template file on disk | Mapping current when saved | `name`, `filePath`, `fieldMapping` map placeholder → column header; keys must match discovered placeholders at save time |
| **DocumentJob** | R/W | drift + PDF files on disk | Progress ≤ 1 s behind | `templatePath`, `dataSheetPath`, `outputDir`, `status`, `progress` (done/failed/total), `startedAt`, `finishedAt`; status monotonic |
| **Per-row failure** | W during job | Embedded in job result / failure list | Immediate at row fail | Row index (1-based data row), `reasonCode`, localized `message` |

**Cache policy:** Last selected template path, data sheet path, output folder may be recalled from AppSettings or feature prefs (implementation choice); not required for acceptance if pickers always start empty.

**Staleness:** Progress display may lag job state by at most 1 second (doc 04).

**File naming:** Output PDFs: `{rowNumber}.pdf` or `{sanitizedKey}.pdf` when a column is designated as key in mapping (optional v1 enhancement — if omitted, row number only).

**Retention:** Completed job metadata pruned after 30 days; PDF files never deleted by app.

## 8. Business rules

| Rule | Statement | When violated |
|------|-----------|---------------|
| R1 | Every discovered template placeholder must map to exactly one data-sheet column header before **Generate PDFs** is enabled | Button stays disabled; inline hint en *"Map all placeholders before generating"* / es *"Mapee todos los marcadores antes de generar"* |
| R2 | Data sheet must contain a header row; data rows are all rows after row 1 | Missing header → error state R-error sheet unreadable |
| R3 | Empty data rows (all mapped cells blank) are skipped, not errors | Skipped rows do not increment success or failure counts; noted in summary en *"{n} empty rows skipped"* / es *"{n} filas vacías omitidas"* if n > 0 |
| R4 | Output directory must be writable before job starts | Job does not start; error state output not writable |
| R5 | A row failure does not abort the whole batch | Remaining rows continue; partial outcome |
| R6 | Saved mapping applies only to the same template file path | Different path → treat as new template |
| R7 | Template static content (logo, layout) comes only from the user template file | App does not inject branding |
| R8 | Batch job runs without network | No network calls during generate |
| R9 | User-visible paths show basename only in lists and summaries | Full paths never shown in UI (NFR8) |

## 9. Error handling

| Failure mode | Detection | User surface | Recovery | Retry | Logging |
|--------------|-----------|--------------|----------|-------|---------|
| Template file missing or locked | Open/read fails | Error: unreadable template | Choose different template | User picks new file | `document_factory.template_read_failed` — no full path |
| Zero placeholders in template | Parser finds none | Partial/warning: zero placeholders | Choose different template | User action | `document_factory.no_placeholders` |
| Data sheet corrupt / not xlsx | Parse fails | Error: unreadable data sheet | Choose different sheet | User action | `document_factory.sheet_read_failed` |
| Header cell duplicate names | Parser detects duplicates | Error: en *"The data sheet has duplicate column headers. Fix the sheet and try again."* / es *"La hoja tiene encabezados duplicados. Corrija la hoja e intente de nuevo."* | Fix file externally | Re-select sheet | `document_factory.duplicate_headers` |
| Row missing mapped cell | Cell empty/null for required mapping | Per-row failure list entry | Fix sheet; re-run batch | **Generate PDFs** again | Row index + reason code only |
| Row render failure | PDF engine throws | Per-row failure: en *"Could not create PDF for this row"* / es *"No se pudo crear el PDF para esta fila"* | Re-run after fix | **Generate PDFs** | Row index + failure type |
| Output disk full | Write fails | Error + failed row entries | Free space; new folder | User action | `document_factory.disk_full` — no path |
| Job interrupted (app exit) | Job status incomplete on relaunch | Interrupted message | Start new batch | **Generate PDFs** | `document_factory.job_interrupted` |
| Mapping save fails | Local store write fails | Snackbar en *"Could not save mapping. Try again."* / es *"No se pudo guardar el mapeo. Intente de nuevo."* | Retry save | **Save mapping** | `document_factory.mapping_save_failed` |

All failures use typed failure enums at domain boundary (FLS-04); no silent catch. User never sees stack traces.

## 12. Accessibility

- **Semantics:** All buttons and dropdowns have labels matching visible text in active locale.
- **Primary actions:** en *"Choose template"*, *"Choose data sheet"*, *"Save mapping"*, *"Choose output folder"*, *"Generate PDFs"*, *"Open output folder"* — es *"Elegir plantilla"*, *"Elegir hoja de datos"*, *"Guardar mapeo"*, *"Elegir carpeta de salida"*, *"Generar PDFs"*, *"Abrir carpeta de salida"*.
- **Traversal order:** Top to bottom: template → data → mapping → output → generate → status.
- **Focus on entry:** First focusable control is **Choose template** (or first unresolved mapping field if returning with incomplete map).
- **Focus on error:** Focus moves to summary error region; screen reader announces title + message.
- **Async announcements:** Progress updates announce every 10% change or every 5 seconds, whichever is less frequent: en *"{done} of {total} PDFs generated"* / es *"{done} de {total} PDFs generados"*.
- **Failure list:** Each row: en *"Row {n}: {message}"* / es *"Fila {n}: {message}"* — list semantics `List`.
- **Tap targets:** Minimum 48×48 logical pixels for all tappable controls.
- **Contrast:** Material 3 theme tokens; error text meets WCAG AA against surface.
- **200% text scale:** Layout scrolls; no clipped primary actions; mapping dropdowns remain usable.
