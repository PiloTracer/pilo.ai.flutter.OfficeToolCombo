# Settings and locale

## 1. Purpose and user value

**Feature id:** FT-06 · **Cross-cutting configuration for the whole app**

A user sets the application language (English or Spanish), appearance (light, dark, or follow system), how often prices are polled, and how long scan history is kept. Their choices apply immediately across all tools and **must still apply after they quit the app and cold-start it again** — especially the language choice, which is non-cuttable for the commercial product (doc 01 §4b, doc 02 §5).

**User value:** Bilingual office staff and buyers can run every tool in their preferred language without re-selecting it each session; coordinators can tune background behaviour and retention from one place.

**Traceability:** FR7 · FR10 · NFR13 · doc 02 §5 · doc 04 §1 (`AppSettings`)

---

## 2. Scope

### In scope

- Settings surface at `/settings` with controls for: **Language**, **Theme**, **Price poll interval**, **Scan history retention**.
- Language options: **English** and **Spanish** only.
- Persist every setting to local storage (`AppSettings`); apply on change without a Save button.
- **Locale persistence across process quit and cold start** — verified by integration test (NFR13).
- Bootstrap default when no stored locale: use OS/system locale if it is `en` or `es`, otherwise **English** (`en`).
- All user-visible strings on the settings screen (and app-wide) sourced from ARB files with keys in both `app_en.arb` and `app_es.arb` (FR10).
- Six UI states on the settings surface (§6).
- Theme applies app-wide immediately (light / dark / system).

### Out of scope

- Additional locales beyond `en` and `es` (doc 02 §5).
- RTL layout.
- Per-tool settings overrides (each tool uses global AppSettings).
- Export/import settings file.
- Cloud sync of preferences.
- Log level UI (stored in schema but not exposed v1).
- Account, auth, or profile settings.

## 4. User flows

### F1 — Change language to Spanish

1. User opens **Settings** from the app shell (route `/settings`).
2. User opens **Language** control and selects **"Español"** (stored value `es`).
3. Entire app UI re-renders in Spanish immediately, including home tool labels and the settings screen itself.
4. User quits the application completely (process exit).
5. User cold-starts the application.
6. First meaningful frame (home shell) is already in Spanish — no flicker to English.

### F2 — Change language to English (inverse of F1)

Same as F1 with **"English"** (`en`); cold start remains English.

### F3 — First launch (no prior stored locale)

1. User launches app for the first time on a system whose language is Spanish.
2. App opens in Spanish without visiting settings.
3. Settings **Language** control shows **"Español"** selected.

**Variant:** System locale is French → app opens in English; Language control shows **"English"**.

### F4 — Change theme

1. User on settings selects **Theme** → **"Dark"** (options: **"Light"**, **"Dark"**, **"System"**).
2. App theme updates immediately.
3. Quit and cold start → dark theme still applied (if **"Dark"** selected); **"System"** follows OS on each start.

### F5 — Change price poll interval

1. User sets **"Price poll interval"** to one of: **5 min**, **10 min** (default), **15 min**, **30 min**.
2. Value persists; price monitor (FT-04) reads new interval on next poll cycle.

### F6 — Change scan retention

1. User sets **"Scan history retention"** to one of: **30 days**, **90 days** (default), **180 days**, **365 days**.
2. Value persists; barcode inventory purges events older than retention on next app start and daily thereafter.

### F7 — Abandonment and back

- User changes Language but navigates Back before render completes: last successfully persisted value applies.
- Back from settings → previous route (typically home `/`).

## 6. UI states

Applies to **`/settings`** only.

| State | User sees | User can do |
|-------|-----------|-------------|
| **Loading** | Previous theme/locale applied globally; settings body shows skeleton rows or **"Loading settings…"** for ≤ 300 ms while `AppSettings` loads | Wait; Back works |
| **Empty** | N/A — singleton settings row always exists after F0 migration; if row missing, treat as **Error** | — |
| **Partial** | Some controls populated, one field failed to load — show loaded values with inline **"Could not load all settings."** on failed control only | Change loaded fields; Retry on failed field |
| **Error** | Full-screen inline **"Could not load settings. Try again."** with **"Retry"**; controls disabled | Tap **"Retry"**; Back to home |
| **Offline** | All controls enabled; footnote **"Settings are saved on this device. No internet required."** | Change any setting — saves locally |
| **Success** | All four controls reflect stored values; changes persist immediately with brief **"Settings saved"** confirmation (snackbar, 2 s, non-blocking) | Change any setting; navigate Back |

**Global locale application:** While settings is in **Loading**, the app still displays using the last known locale (or bootstrap default §7) — never an unlocalized mixed state.

## 7. Data contract

| Entity | Read / write | Source of truth | Freshness |
|--------|--------------|-----------------|-----------|
| `AppSettings` | R/W | drift `app_settings` single row `id = 1` | Immediate on each change |
| Bootstrap mirror | R at cold start | shared_preferences scalars for locale/theme only | Must match drift after write within same session |

**Fields**

| Field | Type | Default | Valid values |
|-------|------|---------|--------------|
| `locale` | string | derived (see R1) | `en`, `es` |
| `themeMode` | enum | `system` | `light`, `dark`, `system` |
| `pricePollMinutes` | int | `10` | 5, 10, 15, 30 |
| `scanRetentionDays` | int | `90` | 30, 90, 180, 365 |

**Locale bootstrap (cold start, before first frame)**

1. Read persisted `locale` from local store.
2. If absent or invalid: if system locale language code is `en` or `es`, use it; else use `en` (R1).
3. Apply locale to `MaterialApp` before building home.

**Cache:** In-memory copy for session; invalidated on successful write.

**Validation:** Reject writes outside valid value sets; UI only offers valid options — invalid drift data falls back to defaults per field with non-blocking **"One setting was reset to default."** banner.

## 8. Business rules

| Rule | Statement | If violated |
|------|-----------|-------------|
| R1 | When no valid stored locale exists, default is system locale if `en` or `es`, else `en` | App displays English |
| R2 | Stored locale must be exactly `en` or `es` | Fall back to R1 derivation |
| R3 | Locale change applies to all surfaces on next frame without restart | N/A — observable behaviour |
| R4 | Locale survives process quit and cold start unchanged | N/A — verified by A2 |
| R5 | Every user-visible string in the app uses an ARB key present in both `app_en.arb` and `app_es.arb` | Release blocked by FR10 / NFR13 CI |
| R6 | Settings writes are durable before showing **"Settings saved"** | Snackbar only after successful persist |
| R7 | `pricePollMinutes` default is 10 | NFR9 |
| R8 | `scanRetentionDays` default is 90 | Matches doc 04 §1 `ScanEvent` retention |
| R9 | Theme **"System"** follows OS light/dark on each cold start | User sees OS-appropriate theme |

## 9. Error handling

| Failure | Detection | User sees | Recovery | Retry | Logged |
|---------|-----------|-----------|----------|-------|--------|
| Settings load failure | drift read error | **"Could not load settings. Try again."** + **"Retry"** | Tap Retry | Yes | storage error class |
| Settings write failure | drift write error | **"Could not save settings. Try again."** on affected control; prior value restored in UI | User re-selects value | Manual | write failure type |
| Invalid stored locale | Not `en`/`es` | Silent fallback per R1/R2; no crash | User may re-select language | N/A | invalid locale warning |
| Corrupt row / missing row | Migration or query anomaly | Defaults applied; **"One setting was reset to default."** if any field reset | User confirms values | N/A | schema recovery event |

No user-facing error exposes SQL, file paths, or stack traces.

## 10. Offline behaviour

| Aspect | Behaviour |
|--------|-----------|
| Cold start offline | Locale and all settings load from local store; fully functional |
| Change settings offline | All changes persist locally; **"Settings saved"** shown |
| Sync | None |
| User indication | **"Settings are saved on this device. No internet required."** when offline (§6) |

Network never required for settings (doc 02 §4).

## 11. Permissions and platform

No runtime permissions. Settings behave identically on Linux, macOS, and Windows.

**System locale detection:** Uses platform locale API at cold start only for R1 default — no permission prompt.

**Platform divergence:** None for settings UI itself.

## 12. Accessibility

- Settings icon on home: semantics label **"Settings"** (localized).
- Traversal order: Language → Theme → Price poll interval → Scan retention → Back.
- On entry, focus first control (**Language**).
- Each option announces state when selected (e.g. **"Español, selected"**).
- **"Settings saved"** announced via live region.
- All controls keyboard-operable; minimum 48 logical px tap height at 100% scale; usable at 200% text scale without clipping primary actions (NFR6).
- Section headers marked as headers for screen readers.
