# Home shell and navigation

## 1. Purpose and user value

**Feature id:** FT-00

The user lands on a single home screen that lists all five OfficeToolCombo tools by name in the **current app locale**, taps one to open that tool, and returns to the same home list. The home shell provides orientation and routing only — no tool business logic runs here.

**User value:** Non-technical staff discover and reach every paid job from one place without memorizing routes or using a terminal.

**Traceability:** FR1 · doc 01 §4 · doc 05 FT-00

---

## 2. Scope

### In scope

- Home route `/` showing exactly five tool entries.
- Each entry: localized title, localized subtitle, navigation to the tool route on tap.
- Back navigation from any tool returns to home.
- Settings entry point on home app bar → `/settings` (FT-06).
- App title **"OfficeToolCombo"** in app bar (brand string — same in all locales per ARB or fixed product name key).
- Six UI states on home surface (§6).
- Labels update immediately when locale changes in settings.

### Out of scope

- Tool-specific logic, forms, or data display on home.
- Role-based hiding of tools.
- Search, favourites, or reordering tools.
- Deep links into individual tools (v1 — routes exist but link handling is not a home requirement).
- Authentication gates.

---

## 3. Actors and preconditions

| Actor | Any OfficeToolCombo user |

**Preconditions**

- Router initialized with six routes: home, five tools, settings (settings via app bar, not list item).
- l10n delegates loaded for current `AppSettings.locale`.
- Minimum window width 1024 logical px (doc 02 §3) — layout is a vertical list; no horizontal scroll on home at default scale.

---

## 4. User flows

### F1 — Open a tool and return

1. User cold-starts app → lands on `/`.
2. Home shows five tools in fixed order (see §5).
3. User taps **"Report consolidator"** (or localized equivalent).
4. App navigates to `/tools/report-consolidator`.
5. User activates Back (app bar or platform shortcut).
6. App shows `/` with the same five entries; no tool state shown on home.

Repeat for each of the five tools.

### F2 — Locale change reflection

1. User on home in English.
2. User opens Settings, selects **"Español"**.
3. User navigates Back to home.
4. All five tool titles and subtitles appear in Spanish.

### F3 — Settings access

1. User on home taps Settings affordance (gear icon).
2. App navigates to `/settings`.
3. Back returns to home.

### F4 — Abandonment

- User taps a tool then immediately Back: home list unchanged, scroll position reset to top (acceptable v1 — scroll restoration not required).

## 6. UI states

Applies to **`/`** only.

| State | User sees | User can do |
|-------|-----------|-------------|
| **Loading** | App bar with title; body shows five skeleton rows or centered **"Loading…"** for ≤ 300 ms while locale/settings resolve | Wait |
| **Empty** | N/A — five tools are static content, not data-driven; list never empty post-F0 | — |
| **Partial** | N/A — no partial data on home | — |
| **Error** | **"Could not start the app. Restart OfficeToolCombo."** with **"Retry"** if router/bootstrap failed | Retry or quit |
| **Offline** | Full home list with footnote **"Some tools work offline. Price monitor needs internet."** | Navigate to any tool |
| **Success** | Five tappable rows with localized title, subtitle, and chevron; Settings visible | Open any tool or Settings |

## 7. Data contract

| Data | Read | Write | Source |
|------|------|-------|--------|
| Current locale | yes | no | `AppSettings` via l10n |
| Tool list | static | no | Defined in SPEC §5 — not user-editable |

**Staleness:** Tool labels reflect locale immediately on settings change (F2).

**Cache:** l10n strings cached by Flutter gen-l10n for session.

## 8. Business rules

| Rule | Statement | If violated |
|------|-----------|-------------|
| R1 | Home always shows exactly five tools in the order in §5 | Layout bug — test fails |
| R2 | Tool titles and subtitles come from ARB keys, not hardcoded literals in the home view | FR10 CI failure |
| R3 | Tapping a row navigates to the matching `/tools/…` route | Navigation test failure |
| R4 | Home contains no input fields, progress bars, or tool-specific actions | Scope violation |
| R5 | Back from any tool route returns to `/` | FLS-05 navigation test |

---

## 9. Error handling

| Failure | User sees | Recovery |
|---------|-----------|----------|
| Unknown route / router error | **"Not found"** app bar + **"Route not found"** body (existing router error surface) | Navigate home via app menu or restart |
| Bootstrap failure before home | **"Could not start the app. Restart OfficeToolCombo."** | Retry / restart |

No tool failures surface on home — tools handle their own errors after navigation.

---

## 10. Offline behaviour

Home loads without network. All five entries remain tappable. Footnote in offline state (§6) informs that price monitor may show offline inside the tool.

Consolidator, inventory, document factory, and backup tools operate offline at cold start (doc 02 §4).

---

## 11. Permissions and platform

No runtime permissions on home. Identical behaviour Linux, macOS, Windows.

**Back behaviour:** Platform Back from a tool pops to home (doc 03 NAVIGATION_STANDARD §5).

---

## 12. Accessibility

- Each tool row: semantics button, label = title + subtitle.
- Traversal order: tool 1 → tool 2 → … → tool 5 → Settings.
- Settings icon: semantics **"Settings"**.
- Keyboard: Enter on focused row navigates to tool.
- Tap targets: full row height minimum 48 logical px at 100% scale; usable at 200% text scale (NFR6).
