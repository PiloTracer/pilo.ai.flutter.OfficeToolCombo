# Report consolidator — FT-01

**Traceability:** `20260802-05-feature-map-and-slices.md` FT-01 · FR2 · NFR7 · NFR10 · doc 04 entities `WorkbookBatch`, `SpreadsheetFile` · doc 02 §4 local-first.

**Localisation:** All user-visible copy lives in ARB keys under the `consolidator_*` namespace. English strings below are the canonical review text; every key **must** have a Spanish equivalent in `app_es.arb` with the same meaning (not a literal word-for-word constraint, but no missing keys at ship).

---

## 1. Purpose and user value

**FT-01** lets a desk-based office coordinator merge many branch `.xlsx` reports into one clean workbook without opening a terminal or re-keying data by hand.

The user selects a folder of spreadsheets, chooses where the merged file is saved, and receives a single output workbook plus a readable list of any files that could not be merged. Progress is visible during the run; the app does not crash when some inputs are corrupt or incompatible. The last source folder is remembered so repeat monthly jobs require one fewer step.

---

## 2. Scope

### In scope

- Pick a **source folder** containing `.xlsx` files (non-recursive: files in the chosen folder only).
- Pick an **output file path** (save dialog) for the consolidated workbook; default filename suggestion `"consolidated.xlsx"`.
- Merge all readable workbooks into one sheet: first file establishes the header row; subsequent files contribute data rows only when their header matches; mismatched headers are failures, not silent duplicates.
- Per-file **progress** indicator (0–100%) during merge.
- **Failure list** for broken files (unreadable/corrupt/empty first sheet) and header-mismatch files; merge continues for good files.
- **Remember last source folder** across app restarts (output path is not remembered — operator chooses each run).
- Full operation **offline** (no network required).
- Six UI states on the consolidator surface (§6).
- English and Spanish UI (§ l10n note above).

### Out of scope

- Subfolder recursion, `.xls`/`.csv` input, Excel macro preservation, or formula recalculation.
- Cloud upload, email send, or scheduled/automatic merges.
- Editing merged data inside the app.
- Undo/rollback of a written output file (operator uses filesystem backup).
- Choosing merge column mapping or custom deduplication rules.
- Batch history UI beyond what the current run surfaces (optional drift metadata is allowed but not required for acceptance).

## 4. User flows

### 4.1 Happy path — full merge

1. User opens **Report consolidator** from home (`/tools/report-consolidator`).
2. Surface shows **empty** state (§6) with primary action.
3. User activates **"Choose source folder"** (`consolidator_chooseSourceFolder`) — native folder picker opens; user confirms a folder.
4. If a last source folder was stored, the picker **opens to that folder** (platform-native behaviour where supported; otherwise path is pre-filled in a secondary label showing last folder basename).
5. User activates **"Choose output file"** (`consolidator_chooseOutputFile`) — native save dialog; user confirms path/filename.
6. User activates **"Merge spreadsheets"** (`consolidator_merge`) — enabled only when both paths are set.
7. Surface enters **loading** state; progress updates until complete.
8. On success with zero per-file failures → **success** state: shows output basename, row/file counts, action to start another merge.
9. User may use **"Back to home"** (`consolidator_backToHome`) at any time when not loading; in-flight merge is cancelled only if the user confirms the dialog **"Cancel merge?"** / **"Keep merging"** (`consolidator_cancelMergeTitle`, `consolidator_cancelMergeKeep`, `consolidator_cancelMergeConfirm`).

### 4.2 Partial success — some files failed

Same as §4.1 through step 7. When at least one file merged and at least one file failed → **partial** state: success summary plus **"Failed files"** list (`consolidator_failedFilesHeading`). Output file is still written with rows from successful files.

### 4.3 Empty folder

User picks a folder with no `.xlsx` files → **empty** state: **"No spreadsheets found"** / **"That folder did not contain any .xlsx files to merge. Choose a different folder."** (`consolidator_emptyTitle`, `consolidator_emptyMessage`). No output file written; last source folder still updated.

### 4.4 Total failure

All files fail or output cannot be written → **error** state with specific message (§9). Any partial parse results are discarded if output write fails.

### 4.5 Abandonment

- User dismisses folder or save picker without selection → remain on current state; no merge starts.
- User navigates **Back to home** while loading → confirmation dialog; on confirm, merge stops and partial output file is deleted if it was created mid-write.
- User closes app while loading → merge stops; no guarantee of partial output (operator re-runs).

### 4.6 Offline

Identical to online flows. If the OS reports no connectivity, surface may show **offline** variant of success/partial (§6) with badge **"Working offline"** (`consolidator_offlineBadge`) — behaviour is unchanged.

## 6. UI states

Applies to the consolidator surface at `/tools/report-consolidator`.

### Loading

- **When:** Merge job running after user confirms paths.
- **User sees:** Primary actions disabled; circular progress; text **"Merging spreadsheets… {percent}%"** (`consolidator_mergingProgress`, `{percent}` integer 0–100). Previous path selections remain visible (not cleared).
- **User can:** Cancel via back navigation (with confirmation) only — cannot pick new paths until job ends or is cancelled.

### Empty

- **When:** Selected source folder contains zero `.xlsx` files, or user landed with no prior run and no paths chosen (initial visit).
- **User sees:** Inbox-style icon; **"No spreadsheets found"** title; explanatory message (§4.3). Distinguished from error by icon/title — no red error styling.
- **User can:** Choose a different source folder or output path; merge remains disabled until valid `.xlsx` exist.

### Partial

- **When:** Merge finished; output written; one or more files in failure list; at least one file contributed rows.
- **User sees:** **"Merged with some failures"** (`consolidator_partialTitle`); output saved line **"Saved as {filename}"** (`consolidator_savedAs`); **"Failed files"** section listing each basename and reason (§9). Success icon with warning accent on failure section.
- **User can:** Read failure reasons; start a new merge (paths retained); return home.

### Error

- **When:** Unrecoverable job failure — all files failed, folder unreadable, output not writable, unexpected failure, or user-cancelled write.
- **User sees:** Error icon; **"Merge failed"** (`consolidator_errorTitle`); specific `errorMessage` from §9 (never a stack trace).
- **User can:** Retry by adjusting paths and pressing merge again; failure list shown if any per-file failures preceded the fatal error.

### Offline

- **When:** Merge completes (success or partial) while device has no network connectivity.
- **User sees:** Same content as success or partial plus subtle **"Working offline"** badge — no blocking banner.
- **User can:** Everything success/partial allows; no retry-for-network required.

### Success

- **When:** Merge finished; output written; zero per-file failures; at least one file merged.
- **User sees:** **"Merge complete"** (`consolidator_successTitle`); **"Saved as {filename}"** or **"Output saved in the selected folder."** when basename unavailable (`consolidator_savedAs`, `consolidator_savedInFolder`); summary **"{fileCount} files merged, {rowCount} rows"** (`consolidator_summary`).
- **User can:** Start another merge; navigate home. Boundaries: works for 1 file and for up to reference batch of 100 files (NFR10, UNK-001).

## 7. Data contract

| Entity | Read / write | Source of truth | Notes |
|--------|--------------|-----------------|-------|
| **WorkbookBatch** | Write per run (optional persistence) | In-memory for UI; optional drift `workbook_batches` | `sourceFolderUri`, `outputPath`, `status`, timestamps |
| **SpreadsheetFile** (result row) | Read during/after run | In-memory on batch | `fileName` (basename only in UI), `parseStatus`, `errorMessage` |
| **Last source folder** | Read on entry; write after successful folder pick | drift `app_settings` key `consolidator_last_source_folder` or dedicated settings row | URI string; never shown as full path in UI — basename + parent hint only |
| **Merged workbook** | Write once per successful/partial run | User-chosen output path on disk | Overwrite requires no extra confirmation if save dialog already confirmed target |

**Validation**

- Source folder must exist and be readable before merge starts.
- Output parent directory must exist and be writable before merge starts.
- Only files ending in `.xlsx` (case-insensitive) are candidates.
- First successfully parsed non-empty file sets the header row for the batch.

**Freshness:** N/A — batch job, no live sync.

**Cache:** In-run file list and progress are ephemeral; last source folder persists until user picks a new folder.

## 8. Business rules

| ID | Rule | When violated |
|----|------|---------------|
| R1 | Merge considers only `.xlsx` files directly in the chosen source folder (not subfolders). | Subfolder files ignored silently. |
| R2 | The first successfully parsed non-empty workbook defines the header row for the merged sheet. | If no file yields a header, job ends in error **"No readable spreadsheets found"** (`consolidator_noReadable`). |
| R3 | For each subsequent workbook, if the first row equals the established header (same column count and cell values), only data rows (row 2+) are appended. | If first row differs → file marked failed with **"Header row does not match the first workbook"** (`consolidator_headerMismatch`); its rows are not appended; merge continues. |
| R4 | A workbook with no rows on the first sheet is a per-file failure: **"Workbook has no rows on the first sheet"** (`consolidator_emptySheet`). | Listed in failure list; other files continue. |
| R5 | A workbook that cannot be decoded is a per-file failure: **"Could not read workbook"** (`consolidator_unreadableFile`) plus non-technical detail if available. | Listed in failure list; app does not crash. |
| R6 | If at least one file contributes rows, the output workbook is written to the user-chosen path even when other files fail. | Partial state (§6). |
| R7 | If every candidate file fails, no output file is written; batch status is failed. | Error state **"All spreadsheets failed to merge"** (`consolidator_allFailed`). |
| R8 | After user confirms a source folder via picker, that folder URI is persisted as last source folder before merge starts. | Next visit pre-selects/opens to that folder (§4.1 step 4). |
| R9 | Progress percentage equals `(files processed / total candidate files) × 100`, rounded to integer. | Shown in loading state; reaches 100% before success/partial/error transition. |
| R10 | User-visible paths and errors use **basename** only; full filesystem paths never appear in UI or failure list. | Applies to logs per NFR8 separately (§14). |
| R11 | Merge runs without network; connectivity state does not block the job. | Offline badge only (§6). |

## 9. Error handling

| Failure mode | Detection | User sees | Recovery | Logged |
|--------------|-----------|-----------|----------|--------|
| Folder picker cancelled | Null/empty picker result | No change | Pick again | No |
| Folder does not exist / unreadable | IO on list | **"Could not read folder: {detail}"** (`consolidator_unreadableFolder`) | Pick different folder | Yes — failure type, no full path |
| Empty folder (no `.xlsx`) | Zero candidates | Empty state (§6) | Pick different folder | Info — file count 0 |
| Per-file corrupt/unreadable | Parse exception | Failure list entry **"Could not read workbook"** | Fix/replace file; re-run | Yes — basename + exception class |
| Per-file empty sheet | Zero rows | Failure list **"Workbook has no rows on the first sheet"** | Fix file; re-run | Yes |
| Per-file header mismatch | Header compare fails R3 | Failure list **"Header row does not match the first workbook"** | Fix file; re-run | Yes — basename |
| Output not writable | Write failure | **"Could not write consolidated workbook: {detail}"** (`consolidator_writeFailed`) | Choose different output path | Yes |
| All files failed | R7 | **"All spreadsheets failed to merge"** | Fix sources; re-run | Yes |
| Unexpected error | Uncaught in job boundary | **"Something went wrong during merge."** (`consolidator_unexpected`) | Retry merge | Yes — stack in debug |
| User cancels during merge | Back + confirm | **"Merge was cancelled"** (`consolidator_cancelled`) | Start again | Info |

**Retry policy:** Merge is idempotent from user perspective — user may re-run after fixing files; output overwrite follows save-dialog confirmation. No automatic retry of failed files.

**Crash policy:** Per-file failures never abort the whole job except when R7 applies or output write fails.
