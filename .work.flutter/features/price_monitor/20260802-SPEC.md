## 1. Purpose and user value

**Feature id:** FT-04 — Price monitor

**Job to be done:** A buyer or ops user tracks multiple product prices from the web, gets alerted when a price crosses a threshold they set, and can manage watches from the UI without scripts or browser extensions.

**User value:** The operator creates one or more **price watches** (label, URL, threshold, direction above/below), enables or disables each watch, and sees the **last-known price** per watch. While the app runs (including minimized), enabled watches are polled on a default **10-minute** interval. When a fetched price crosses the threshold, the user receives an **OS notification**; if the OS cannot show a notification, an **in-app banner** appears instead. When offline, watches show an **offline badge** and polling pauses; **other tools remain fully usable** without network (doc 02 §4, probe C3).

**Success signal (from doc 01 J4):** Multi-watch CRUD from UI; background poll; OS alert while app minimized; offline badge visible.

---

## 2. Scope

### In scope

- **Multi-watch CRUD:** Create, read, update, delete price watches from `/tools/price-monitor`.
- **Enable / disable** per watch without deleting it; disabled watches are not polled and do not notify.
- **Threshold** stored and compared as **Decimal** (not floating point); user enters threshold in UI as decimal string validated to > 0.
- **Direction:** notify when price goes **above** or **below** threshold (per watch).
- **Background poll:** Default interval **10 minutes** between fetch attempts for enabled watches (NFR9, AppSettings `pricePollMinutes` default 10).
- **Price fetch:** HTTP GET to watch URL; parse price from response (HTML/JSON — parsing strategy is implementation; behaviour: a single numeric price extracted or fetch marked failed).
- **Last-known price:** Display latest successful sample per watch with fetch timestamp in user locale format.
- **Threshold cross notification:** When a new fetch crosses threshold relative to prior sample (or first fetch after enable — see R4), deliver OS notification with watch label and price; on OS notification failure, show in-app banner fallback.
- **Offline badge:** Visible on price monitor screen and per watch when connectivity unavailable; polling skipped.
- **Other tools offline:** Consolidator, inventory, document factory, backup operate at cold start without network; price monitor does not block app shell (NFR7).
- **Six UI states** on watch list surface (§6).
- **Bilingual UI:** all strings en/es.

### Out of scope

- Price history charts or export (latest sample only for display v1 — doc 04 optional history).
- Sub-minute polling or user-configurable poll interval in UI (default from settings row only; changing interval is settings scope, not watch editor v1).
- Authenticated APIs, cookies, or CAPTCHA bypass.
- Multiple currencies conversion.
- Push notifications when app is not running (desktop v1: poll while process alive).
- Browser automation or headless rendering of JavaScript-heavy pages beyond what HTTP fetch returns.
- Competing watches deduplication across URLs.

## 4. User flows

### 4.1 Create and enable a watch

1. **Entry:** Home → **Price monitor** → `/tools/price-monitor`.
2. User taps **Add watch** → editor opens (sheet or route — single surface).
3. User enters: **Label** (required), **URL** (required), **Threshold** (required, Decimal > 0), **Notify when** *Above* or *Below*, **Enabled** toggle default on.
4. User taps **Save** → watch appears in list with last-known price en *"Not fetched yet"* / es *"Sin consultar aún"* if no sample.
5. First poll scheduled within current interval policy.

### 4.2 Edit / disable / delete

1. User selects watch → **Edit** → changes fields → **Save**.
2. User toggles **Enabled** off on list row → watch greyed; polling stops; no notifications.
3. User **Delete** → confirmation en *"Delete this watch?"* / es *"¿Eliminar este seguimiento?"* → confirm → watch removed.

### 4.3 Threshold cross alert

1. Enabled watch polled; new price parsed.
2. If price crosses threshold per direction rule (R3, R4) → OS notification: title en *"Price alert: {label}"* / es *"Alerta de precio: {label}"*; body en *"Price is {price} (threshold {threshold})"* / es *"El precio es {price} (umbral {threshold})"*.
3. If OS notification fails → in-app banner (§9) with same text; banner dismissible.
4. User opens app → watch row shows updated last-known price and timestamp.

### 4.4 Offline

1. Network lost → global offline badge on screen; each enabled watch row shows offline indicator.
2. Polls skipped; last-known price and timestamp unchanged with suffix en *"(offline)"* / es *"(sin conexión)"* on badge only, not duplicated in price text.
3. User opens consolidator or other tools → those tools work normally.

### 4.5 Abandonment

1. User leaves price monitor while polls continue in background.
2. User quits app → polling stops until next launch; no notification for crosses that occurred while app closed (v1 explicit limitation — out of scope push).

### 4.6 Back behaviour

- App bar back → home; editor **Cancel** discards unsaved edits with confirm if dirty.

## 6. UI states

Applies to watch list at `/tools/price-monitor`.

### Loading

- **When:** Initial load of watches from local store; first connectivity check; immediately after **Save** before list refresh.
- **User sees:** Skeleton list OR spinner with en *"Loading watches…"* / es *"Cargando seguimientos…"*; **Add watch** may be disabled briefly.
- **User can:** Navigate back to home.

### Empty

- **When:** Zero watches in database.
- **User sees:** Icon `watch_off` or equivalent; title en *"No price watches yet"* / es *"Aún no hay seguimientos de precio"*; message en *"Add a watch to get notified when a price crosses your threshold."* / es *"Agregue un seguimiento para recibir avisos cuando un precio cruce su umbral."*; **Add watch** prominent.
- **Distinct from error:** Neutral colour; no retry.

### Partial

- **When:** Some watches have last-known price; others never fetched successfully or last fetch failed; OR mixed online/offline per watch is not used — global offline only; partial means list loaded but some rows show en *"Fetch failed"* / es *"Consulta fallida"* instead of price.
- **User sees:** Successful rows with price + time; failed rows with warning icon and en *"Could not read price from page"* / es *"No se pudo leer el precio de la página"*; **Retry now** on row (manual single-watch poll).
- **User can:** Edit watch URL; retry fetch; disable watch.

### Error

- **When:** Local store read fails; unrecoverable load error.
- **User sees:** Title en *"Could not load watches"* / es *"No se pudieron cargar los seguimientos"*; message en *"Try closing and reopening the app."* / es *"Intente cerrar y abrir la aplicación de nuevo."*; **Try again** button.
- **Recovery:** **Try again** reloads from local store.

### Offline

- **When:** `ConnectivityService` reports no network.
- **User sees:** Banner/badge en *"Offline — price checks paused"* / es *"Sin conexión — consultas de precio en pausa"* at top of list; per-watch small offline chip; last-known prices still visible (stale); polling paused.
- **Distinct from error:** Amber/info styling, not red error; other app areas unaffected.
- **On reconnect:** Badge clears within one connectivity check cycle; next poll scheduled without user action.

### Success

- **When:** ≥1 watch loaded; online or offline with stale prices allowed; list interactive.
- **User sees:** Watches with label, enabled state, last price formatted per locale (Decimal string), relative or absolute fetch time en *"Updated {time}"* / es *"Actualizado {time}"*; threshold line en *"Alert {above\|below} {threshold}"* / es *"Alerta {above\|below} {threshold}"* with localized above/below: *Above* / *Debajo del* → use es *"Por encima de"* / *"Por debajo de"*.
- **Boundaries:** One watch — list single row; many watches (realistic max 50) — list scrolls with no frame jank (NFR2).

## 7. Data contract

| Entity | Read / write | Source of truth | Freshness | Validation |
|--------|--------------|-----------------|-----------|------------|
| **PriceWatch** | R/W | drift `price_watches` | Immediate on save | `label` non-empty; `url` valid http(s); `threshold` Decimal > 0; `direction` enum above/below; `enabled` bool |
| **PriceSample** | W on fetch | drift `price_samples` | Latest overwrites display | `watchId`, `price` Decimal, `fetchedAt`, `rawStatus` success/failed |
| **AppSettings.pricePollMinutes** | R | drift `app_settings` | Default 10 | Integer ≥ 1 |

**Staleness tolerance:** Display may show price up to one poll interval old plus fetch duration; user informed via timestamp.

**History:** Optional rolling 30-day samples retained (doc 04); UI shows latest only v1.

**No cross-feature FK:** Watches independent of other tools.

## 8. Business rules

| Rule | Statement | When violated |
|------|-----------|---------------|
| R1 | Disabled watches are never polled and never notify | Toggle off → no network for that watch |
| R2 | Threshold must be Decimal strictly greater than zero | Save blocked; field error en *"Enter a threshold greater than zero"* / es *"Ingrese un umbral mayor que cero"* |
| R3 | **Above:** notify when new price ≥ threshold and previous successful sample was < threshold (or no previous sample — see R4) | No duplicate notify for same side until price crosses back |
| R4 | **Below:** notify when new price ≤ threshold and previous successful sample was > threshold | Same anti-repeat logic |
| R5 | First successful fetch after enable does not notify unless price already meets cross condition and operator saved watch with that condition intentional — notify once on first cross detection after enable | Documented: first sample establishes baseline; notify only on transition across threshold |
| R6 | Default poll interval is 10 minutes unless AppSettings changed | Scheduler uses settings value |
| R7 | Polls skipped when offline | No failed spam; last sample unchanged |
| R8 | URL must use http or https scheme | Save error en *"Enter a valid web address starting with http:// or https://"* / es *"Ingrese una dirección web válida que comience con http:// o https://"* |
| R9 | Label max 120 characters | Trim; error if empty |
| R10 | OS notification failure must show in-app banner within 2 seconds with same content | Fallback mandatory (UNK-002 mitigation) |

## 9. Error handling

| Failure mode | Detection | User surface | Recovery | Retry | Logging |
|--------------|-----------|--------------|----------|-------|---------|
| Invalid URL on save | Validator | Inline field error R8 | Fix URL | **Save** | `price_monitor.validation_failed` |
| HTTP timeout / network error | dio timeout | Row: en *"Fetch failed"* / es *"Consulta fallida"*; offline badge if global offline | Wait for reconnect or **Retry now** | Automatic on next poll; manual retry | `watchId`, status class, latency — **no full URL if query has tokens** (NFR8) |
| HTTP 4xx/5xx | Response code | Same row failed state | Fix URL or retry later | Poll interval | status class only |
| Parse failure (no price in body) | Parser returns empty | Row message en *"Could not read price from page"* / es *"No se pudo leer el precio de la página"* | Fix URL or page format | Retry | `price_monitor.parse_failed` |
| OS notification denied (macOS/Windows) | notify API error | In-app banner R10 | User enables OS notifications in system settings; banner still shown | Next cross | `price_monitor.os_notify_failed` |
| OS notification unavailable (Linux DE) | notify API error or UNK-002 matrix | In-app banner R10 — **primary acceptance path on Linux until UNK-002 resolved** | Banner dismiss; watch still updated in list | Next cross | `price_monitor.os_notify_failed`, `platform=linux` |
| Local store read failure | drift error | Full-screen error §6 | **Try again** | User tap | `price_monitor.load_failed` |
| Delete last watch | CRUD | Returns to empty state | **Add watch** | n/a | `price_monitor.watch_deleted` |

> **OPEN: UNK-002** — Which Linux desktop environments receive OS notifications reliably — blocks Linux-only OS notification acceptance (A6 variant); owner Implementer; needed by F4 complete. **Workaround:** A7 in-app banner fallback is mandatory pass on all platforms; OS notification pass required on macOS and Windows; Linux OS notification marked manual DE matrix in F4-T4.

## 10. Offline behaviour

| Capability | Offline |
|------------|---------|
| View watch list and last-known prices | Yes |
| Create/edit/delete/disable watches | Yes (stored locally) |
| Fetch prices | No — paused |
| Receive OS notification for cross | No new fetches — no new crosses |
| Other tools (consolidator, inventory, document factory, backup) | Yes — full local flows (NFR7) |

**Queues:** Watch edits persist immediately; fetch queue drains when online.

**Refused:** Price fetch while offline — not an error dialog; offline badge explains pause.

**On reconnect:** Polling resumes within one poll interval; badge clears.

**Conflict:** None — single device.

## 11. Permissions and platform

| Platform | Notification permission | Divergence |
|----------|-------------------------|------------|
| Linux | May not require explicit grant; DE-dependent (UNK-002) | Banner fallback always implemented |
| macOS | User must allow notifications for app | Denied → banner only; settings deep link copy en *"Allow notifications in System Settings to get price alerts on the desktop."* / es *"Permita notificaciones en Ajustes del sistema para recibir alertas de precio en el escritorio."* |
| Windows | Toast via system; focus assist may suppress | Same banner fallback |

**Network:** Required for fetch only; app cold-starts without network (doc 02).

**Background:** Poll uses desktop-friendly timers while process running (doc 02 §3); no mobile background modes.

**Per-platform parity (FLS-07):** Functional parity = watch CRUD + last price + alert content; delivery channel may differ (OS vs banner on Linux per UNK-002).

## 12. Accessibility

- **Watch list:** Each row is a semantic list item: en *"{label}, last price {price}, updated {time}, alert {direction} {threshold}, {enabled\|disabled}"* / es equivalent.
- **Enabled toggle:** en *"Enable watch {label}"* / es *"Activar seguimiento {label}"* — state announced on change.
- **Offline badge:** en *"Offline, price checks paused"* / es *"Sin conexión, consultas en pausa"* — `liveRegion` polite on appear/clear.
- **Banner fallback:** `alert` role; focus moves to banner on show; **Dismiss** en *"Dismiss"* / es *"Descartar"* returns focus to list.
- **Editor fields:** Labels for Label, URL, Threshold, Notify when; threshold input `decimal` keyboard hint desktop-appropriate.
- **Traversal:** List top-to-bottom; **Add watch** before list or after empty state per layout; editor tab order Label → URL → Threshold → Direction → Enabled → Save.
- **Focus on error:** Invalid field receives focus on failed save.
- **200% text scale:** List and editor scroll; toggles remain tappable ≥ 48×48 dp.
