# Barcode inventory — FT-02

**Traceability:** `20260802-05-feature-map-and-slices.md` FT-02 · FR3 · NFR7 · NFR11 · doc 04 entities `InventoryItem`, `ScanEvent` · doc 02 §3 input (USB wedge as keyboard).

**Localisation:** All user-visible copy lives in ARB keys under the `inventory_*` namespace. English strings below are the canonical review text; every key **must** have a Spanish equivalent in `app_es.arb` with the same meaning.

---

## 1. Purpose and user value

**FT-02** lets a stock clerk count and look up on-hand quantity using a **USB barcode wedge** (device behaves as a keyboard — no custom driver). The scan field is always ready for the next scan without clicking; each known barcode increments quantity; unknown barcodes trigger a short create flow (name + starting quantity). A simple stock list supports desk lookup without scanning. All quantities **persist across app restart** on the local device.

---

## 2. Scope

### In scope

- USB wedge input treated as keyboard entry into a dedicated scan field terminated by Enter.
- Scan field **always focused** when the inventory surface is visible and after every successful scan or create; field **cleared** after each scan submission.
- Known barcode: lookup item, increment `quantityOnHand` by 1 (configurable delta = +1 per scan in v1).
- Unknown barcode: modal/dialog create flow — display scanned barcode (read-only), user enters **item name** and **starting quantity** (default 1), confirm creates item and applies first scan.
- On-screen **stock list** sorted by name with barcode and quantity; text filter for lookup by name or barcode substring.
- Persistence via local store (drift `inventory_items`, `scan_events` per doc 04).
- Six UI states on the inventory surface (§6).
- English and Spanish UI.
- Performance: lookup after scan ≤ **200 ms p95** on reference desktop (NFR11).

### Out of scope

- Camera-based barcode scanning, Bluetooth scanner SDKs, or serial-port devices.
- Multi-device sync, cloud backup of inventory, CSV export (P1).
- Decrement/adjustment modes, purchase orders, or negative quantities.
- Printing labels or barcode generation.
- User accounts, roles, or audit export UI (scan events stored but no history screen in v1).
- Scanning while another modal app-wide dialog is open outside this feature.

## 4. User flows

### 4.1 Scan known item

1. User opens **Barcode inventory** from home.
2. Scan field has focus; placeholder **"Scan barcode…"** (`inventory_scanPlaceholder`).
3. User scans wedge → digits appear in field → Enter fires.
4. Within 200 ms p95, UI shows updated quantity for that item in the stock list and a brief confirmation **"Updated {name}: {qty}"** (`inventory_updatedToast`).
5. Field clears and **regains focus** automatically.

### 4.2 Scan unknown item — create

1. Steps 1–3 as above with unknown barcode.
2. **Create item** dialog opens (`inventory_createTitle` **"New item"**); barcode shown read-only; focus on **"Item name"** field (`inventory_itemNameLabel`).
3. User enters name (required, 1–120 chars) and starting quantity (integer ≥ 0, default **1**).
4. User confirms **"Add item"** (`inventory_addItem`) or cancels **"Cancel"** (`inventory_cancel`).
5. On confirm: item created, quantity set to starting value, dialog closes, toast **"Added {name}"** (`inventory_addedToast`), scan field cleared and focused.
6. On cancel: dialog closes, scan field cleared and focused; no DB write.

### 4.3 Desk lookup without scan

1. User types in **"Search stock"** filter (`inventory_searchPlaceholder`).
2. Stock list shows matching items (name or barcode contains filter, case-insensitive).
3. Clearing filter restores full list sorted by name ascending.

### 4.4 Persistence across restart

1. User scans items, creating/updating quantities.
2. User quits app completely.
3. On cold start, user returns to inventory — stock list shows same quantities; new scans continue from persisted values.

### 4.5 Abandonment

- User navigates **Back to home** (`inventory_backToHome`) — inventory state saved incrementally per scan; no unsaved scan buffer beyond in-progress dialog.
- User closes create dialog with Cancel — no item created.
- Partial name entry discarded on cancel.

### 4.6 Rapid consecutive scans

Clerk scans multiple items in succession without touching mouse — each scan processed in order; field never stays populated after a completed scan.

## 6. UI states

Applies to the inventory surface at `/tools/barcode-inventory`.

### Loading

- **When:** Initial load of inventory items from local DB on first frame after navigation.
- **User sees:** Scan field disabled; skeleton or centered spinner; **"Loading inventory…"** (`inventory_loading`).
- **User can:** Wait; back navigation still available.

### Empty

- **When:** DB contains zero items and search filter is empty.
- **User sees:** **"No items yet"** (`inventory_emptyTitle`); **"Scan a barcode to add your first item."** (`inventory_emptyMessage`). Scan field enabled and focused once loading completes.
- **User can:** Scan to open create flow; search yields no rows with **"No matching items"** (`inventory_noMatch`) when filter active.

### Partial

- **When:** Item list loaded but one or more rows failed to hydrate (corrupt row skipped) **or** search filter excludes some items while others display.
- **User sees:** Visible list rows; non-blocking banner **"Some items could not be loaded"** (`inventory_partialBanner`) with count if known; corrupt rows omitted.
- **User can:** Scan and search normally; banner dismissible for session.

### Error

- **When:** DB read fails entirely on load or scan persistence fails.
- **User sees:** **"Could not load inventory"** or **"Could not save scan"** (`inventory_loadError`, `inventory_saveError`); retry action **"Try again"** (`inventory_retry`).
- **User can:** Retry load/save; navigate home. Scan field disabled until load succeeds.

### Offline

- **When:** No network connectivity (including cold start offline).
- **User sees:** Normal inventory operation; optional badge **"Working offline"** (`inventory_offlineBadge`) — identical capabilities to online for this tool.
- **User can:** Scan, create, search — all flows (doc 02 §4, NFR7).

### Success

- **When:** One or more items loaded; DB readable/writable; routine scanning.
- **User sees:** Stock list populated; scan field focused with placeholder; last scan toast fades after 2 s.
- **User can:** Continuous scanning; search; open create for unknown codes. Boundaries: 1 item and **≥ 1 000 items** remain scrollable and meet NFR11 on reference device.

## 7. Data contract

| Entity | Attributes (doc 04) | Source of truth | Validation |
|--------|---------------------|-----------------|------------|
| **InventoryItem** | `sku`, `barcode`, `name`, `quantityOnHand`, `updatedAt` | drift `inventory_items` | Barcode unique; `quantityOnHand` ≥ 0; name non-empty on create |
| **ScanEvent** | `id`, `barcode`, `itemId?`, `scannedAt`, `delta` | drift `scan_events` append-only | Written atomically with item update; `delta` = +1 v1 |

**Scan submission**

- Input: barcode string from field trim; empty rejected silently (no error toast).
- Known barcode: `quantityOnHand += 1`, new `ScanEvent`, `updatedAt` now.
- Unknown barcode: no mutation until create confirmed.

**Create item**

- Input: barcode (from scan), name, starting quantity.
- Output: new `InventoryItem` row; initial `ScanEvent` optional (starting quantity applied directly).

**Search**

- Read-only filter on in-memory list refreshed after each mutation.

**Freshness:** Real-time on scan — list updates before toast dismisses.

**Retention:** Scan events follow AppSettings `scanRetentionDays` (default 90); items until deleted (no delete UI in v1 — out of scope).

## 8. Business rules

| ID | Rule | When violated |
|----|------|---------------|
| R1 | Wedge input is read only through the scan field while inventory surface is top-most route. | N/A — other routes deactivate wedge policy. |
| R2 | On Enter in scan field with non-empty barcode, lookup runs before field clears. | Empty input: clear field, no DB call, no toast. |
| R3 | Known barcode (exact match on `barcode` column): increment quantity by 1. | — |
| R4 | Unknown barcode: open create dialog; do not increment any existing item. | — |
| R5 | Create requires name length 1–120; quantity integer 0–999 999. | Invalid: inline errors **"Enter an item name"** / **"Enter a valid quantity"** (`inventory_nameRequired`, `inventory_qtyInvalid`); confirm blocked. |
| R6 | Barcode uniqueness: creating a barcode that exists shows **"An item with this barcode already exists"** (`inventory_duplicateBarcode`) and confirm blocked. | — |
| R7 | After successful scan or create cancel/confirm, scan field text is empty and focus returns to scan field within 100 ms. | — |
| R8 | While inventory surface visible, if focus leaves scan field without user activating another control inside the surface, focus returns to scan field on next frame ( wedge always ready — does not steal focus from create dialog fields). | Dialog open: focus follows dialog rules; on close, R7 applies. |
| R9 | Stock list sort order: `name` ascending, case-insensitive tie-break by barcode. | — |
| R10 | Search filter matches if name or barcode contains filter substring (case-insensitive). | Empty filter shows all items. |
| R11 | All mutations persist to drift before success toast appears. | Save failure → error state/toast **"Could not save scan"**; quantity not updated in UI. |

## 9. Error handling

| Failure mode | Detection | User sees | Recovery | Logged |
|--------------|-----------|-----------|----------|--------|
| DB load failure | Repository error on init | Error state **"Could not load inventory"** + **"Try again"** | Retry | Yes |
| Save failure on scan | Transaction error | Toast **"Could not save scan"**; prior quantity unchanged | Retry scan | Yes |
| Save failure on create | Transaction error | Inline dialog error **"Could not save item"** (`inventory_createSaveError`) | User edits and retries | Yes |
| Duplicate barcode on create | Unique constraint | **"An item with this barcode already exists"** | User cancels; scan again | Info |
| Invalid create input | Validation | Field-level messages (R5) | Correct fields | No |
| Corrupt single row on load | Mapper skip | Partial banner (§6) | Continue with good rows | Yes — row id |
| Unexpected error | Catch-all | **"Something went wrong"** (`inventory_unexpected`) | Retry or home | Yes — stack debug |

No automatic retry loops — user-initiated retry only.
