# Scheduled backup

## 1. Purpose and user value

**Feature id:** FT-05 · **Job:** J5 (doc 01 §3)

An office manager protects a working folder by creating dated zip archives on a daily schedule or on demand, without using a terminal, cron, or IT help. They choose a source folder, a destination folder, and the hour of day for automatic runs; they can trigger an immediate backup with one prominent action; they see whether the last run succeeded and a list of recent archives so they can trust the job ran.

**User value:** Replaces manual zip copies and IT-maintained cron jobs with a self-service, bilingual desktop flow that never silently overwrites a prior day's archive.

**Traceability:** FR6 · doc 01 §4b (trust surface, zero terminal) · doc 04 §1 (`BackupJob`, `BackupRun`)

---

## 2. Scope

### In scope

- Configure one active backup job: source folder, destination folder, daily run hour (local time, 0–23), schedule enabled/disabled.
- Manual backup via a single primary action button on the backup screen.
- Create a zip archive of the entire source folder tree at run time.
- Archive file name includes the calendar date (`YYYY-MM-DD`) in the basename; archives from prior calendar days are never overwritten.
- Automatic daily run at the configured hour while the app process is running; schedule drift ≤ 1 minute (NFR from doc 04 §3).
- Last-run status (timestamp, outcome, short message) and a list of the 10 most recent archives (name, date, size).
- Actionable, localized errors for missing source, unwritable destination, and other run failures.
- Full offline operation — no network required (NFR7, doc 02 §4).
- All user-visible copy in English and Spanish via ARB keys (FR10).
- Six UI states on the backup surface (§6).

### Out of scope

- Cloud or network backup destinations (doc 01 §4b P1).
- Sub-daily schedules (hourly, every N minutes) — daily hour only (ASM-005).
- Multiple concurrent backup jobs — v1 supports exactly one job configuration.
- Restore or browse archive contents inside the app.
- Running scheduled backups when the app process is not running (no OS-level daemon v1).
- Encrypting or password-protecting archives.
- Selecting individual files — always the whole source folder tree.

| Actor | Description |

## 4. User flows

### F1 — First-time configuration

1. User opens the app home and taps **"Scheduled backup"** (localized).
2. App navigates to `/tools/scheduled-backup`.
3. User taps **"Choose source folder"** and selects a folder in the OS picker.
4. User taps **"Choose destination folder"** and selects a folder.
5. User sets **"Daily run hour"** to a value 0–23 (default **2** = 02:00 local).
6. User leaves **"Enable daily schedule"** on (default on).
7. Configuration is saved when each field changes; no separate Save button.
8. **Exit:** user presses Back → returns to home (`/`). Unsaved picker dialogs cancel without changing stored paths.

### F2 — Manual backup (happy path)

1. User is on the backup screen with valid source and destination configured.
2. User taps the primary button **"Back up now"**.
3. Button disables; progress area shows **"Creating backup…"** and an indeterminate progress indicator.
4. On success: last-run status updates to **"Last backup: succeeded"** with timestamp; new archive appears at top of recent archives list; a brief confirmation **"Backup complete"** is shown (snackbar or inline banner, dismissible).
5. User verifies the zip file exists in the destination folder via OS file manager if desired.

### F3 — Scheduled automatic run

1. App is running (foreground or minimized) with schedule enabled and valid paths.
2. At the configured daily hour (local time), the app starts a backup run automatically without user action.
3. Outcome is recorded identically to a manual run; last-run status and recent archives list update when the user next opens the backup screen (and immediately if the screen is visible).
4. If a run is already in progress at the scheduled hour, the scheduled run is skipped and logged; last-run status reflects the in-progress or completed manual run.

### F4 — Recover from destination not writable

1. User configures destination to a folder they cannot write to (or permissions change later).
2. User taps **"Back up now"** (or schedule fires).
3. Run fails; last-run status shows **"Last backup: failed"** with message **"Cannot write to the destination folder. Choose a different folder or check permissions."**
4. **"Choose destination folder"** remains enabled; user picks a new folder and retries **"Back up now"**.

### F5 — Recover from missing source

1. Source folder is moved or deleted after configuration.
2. User taps **"Back up now"** (or schedule fires).
3. Run fails; message **"Source folder not found. Choose the folder again."**
4. User re-selects source and retries.

### F6 — Abandonment

- User navigates away during an in-progress backup: run continues to completion in the background; last-run status updates regardless of visible screen.
- User closes the app during backup: run is cancelled; last-run status records **"Last backup: failed"** with **"Backup was interrupted."** if partial archive exists, partial file is deleted and not listed in recent archives.

### F7 — Return from home

1. User on backup screen presses Back (or platform equivalent).
2. App navigates to `/` without confirmation when no folder picker is open.

## 6. UI states

Applies to **`/tools/scheduled-backup`** only.

| State | User sees | User can do |
|-------|-----------|-------------|
| **Loading** | Skeleton or previous content with subtle **"Loading…"** indicator for ≤ 300 ms while job config and run history load from local store | Wait; Back still works |
| **Empty** | Configuration fields shown with placeholders **"No source folder selected"** / **"No destination folder selected"**; last-run area shows **"No backups yet"**; recent archives list shows **"No archives yet"** with helper **"Run a backup to see archives here."**; **"Back up now"** disabled until both folders set | Choose folders, set hour/toggle; cannot run backup |
| **Partial** | Stored config visible; recent archives list loaded but last-run record missing or stale — shows **"Last backup: unknown"**; OR last run failed but older archives listed — failure banner above list while archives remain visible | Change config, retry **"Back up now"**, inspect archive list |
| **Error** | Config failed to load — inline error **"Could not load backup settings. Try again."** with button **"Retry"**; form fields disabled | Tap **"Retry"**; Back to home |
| **Offline** | No network badge needed — show neutral inline note **"Backups use local folders only. No internet required."** when connectivity service reports offline; all controls remain enabled | Full configuration and backup flows |
| **Success** | All config fields populated; schedule toggle reflects stored value; last-run shows **"Last backup: succeeded"** or **"Last backup: failed"** with localized detail; up to 10 recent archives with name, localized date, human-readable size; **"Back up now"** enabled when not running | Manual run, change settings, open folders via OS (paths shown as folder name + parent hint, not full path) |

**In-progress run (overlay on Success):** **"Back up now"** disabled, label **"Creating backup…"**, schedule still shown but next automatic run waits until current run finishes.

## 7. Data contract

| Entity | Read / write | Source of truth | Freshness |
|--------|--------------|-----------------|-----------|
| `BackupJob` | R/W | drift `backup_jobs` (single row v1) | Immediate on save |
| `BackupRun` | W on run; R for history | drift `backup_runs` | Immediate after run completes |
| Zip archive | W on run | Destination folder on disk | Exists iff run succeeded |
| `AppSettings` | R (locale only) | drift `app_settings` | For localized labels |

**Fields (behavioural)**

- `sourceFolderUri`, `destinationFolderUri` — non-empty strings from folder picker; validated at run time.
- `dailyRunHour` — integer 0–23, local timezone.
- `scheduleEnabled` — boolean, default true.
- `BackupRun.archivePath` — basename only in UI; full path stored internally, never shown verbatim to user.
- `BackupRun.bytesWritten`, `startedAt`, `finishedAt`, `status` (`succeeded` | `failed` | `cancelled`).

**Archive naming**

- Basename pattern: `OfficeToolCombo-backup-YYYY-MM-DD.zip` using local calendar date at run start.
- If that exact name already exists in the destination (same calendar day re-run), append `-HHmmss` before `.zip` (e.g. `OfficeToolCombo-backup-2026-08-02-143015.zip`).
- **Invariant:** no run may overwrite a zip file whose date component is an earlier calendar day than today (R3).

**Retention:** Run metadata older than 90 days may be pruned from drift; zip files on disk are never deleted by the app.

**Validation**

- Source and destination must be set before manual or scheduled run.
- Source and destination must not be the same path (R4).
- Destination must be writable before zip creation starts.

## 8. Business rules

| Rule | Statement | If violated |
|------|-----------|-------------|
| R1 | A backup run includes all files and subfolders under the source folder at run start | n/a — definition of run scope |
| R2 | Archive basename always contains `YYYY-MM-DD` of the run's local start date | Run fails internally; user sees generic creation failure |
| R3 | A new run must not replace or delete an existing archive file whose embedded date is before the current local calendar day | Run uses alternate name per §7; prior files untouched |
| R4 | Source and destination folder paths must differ | **"Source and destination must be different folders."** — run blocked, no zip created |
| R5 | At most one backup run executes at a time | Second trigger (manual or scheduled) is skipped or queued until first completes; scheduled skip logged |
| R6 | Scheduled run fires once per local calendar day at the configured hour while the app is running | Missed days (app not running) are not backfilled automatically |
| R7 | Failed runs do not add an entry to recent archives list | Last-run status shows failure; list unchanged except for successful runs |
| R8 | Recent archives list shows at most 10 entries, sorted by run `finishedAt` descending | Older successful runs drop from UI list only; files remain on disk |
| R9 | All user-visible strings come from ARB keys in `en` and `es` | N/A at runtime — release gate (FR10) |

## 9. Error handling

| Failure | Detection | User sees | Recovery | Retry | Logged |
|---------|-----------|-----------|----------|-------|--------|
| Source folder missing at run | OS stat before read | **"Source folder not found. Choose the folder again."** | Re-pick source | User taps **"Back up now"** | job id, failure type `sourceMissing`; not full path |
| Destination not writable | Pre-write probe file or mkdir test | **"Cannot write to the destination folder. Choose a different folder or check permissions."** | Re-pick destination | User retries manual run | failure type `destinationNotWritable` |
| Source not readable | OS read error during zip | **"Cannot read the source folder. Check permissions."** | Fix OS permissions or pick new source | Manual retry | failure type `sourceNotReadable` |
| Disk full during zip | Write IOException | **"Not enough space in the destination folder."** | Free space or new destination | Manual retry | bytes written before fail |
| Same source and destination | Validation before run | **"Source and destination must be different folders."** | Change one path | Immediate after fix | validation failure |
| Run interrupted (app exit) | Cancel signal | **"Backup was interrupted."** | Start new run | Manual | status `cancelled`; partial zip removed |
| Config load failure | drift read error | **"Could not load backup settings. Try again."** + **"Retry"** | Tap Retry | Automatic on Retry tap | storage error class |
| Unknown internal error | Uncaught in data layer | **"Backup failed. Try again or check the folders."** | Retry or change paths | Manual | stack in debug only; correlation id |

Paths in user messages use folder **display name** (basename) only, never full home or client path (doc 03 §2, NFR8).

| Platform | Folder selection | Notes |

| Linux | Native directory picker | Primary reference platform |
| macOS | Native directory picker | Same behaviour as Linux |
| Windows | Native directory picker | Long paths (> 260 chars) must not fail silently — user sees **"Path is too long for this system. Choose a shorter destination."** if OS rejects |

## 12. Accessibility

- Every interactive control has a `Semantics` label matching visible text or ARB `semantics*` key.
- Traversal order: source → destination → daily hour → schedule toggle → **"Back up now"** → last-run status → recent archives list (top to bottom, left to right).
- On entering screen, focus moves to first unset required field; if all set, focus on **"Back up now"**.
- When backup completes, screen reader announces **"Backup complete"** or failure message via live region.
- **"Back up now"** minimum tap target 48×48 logical px at 100% scale; remains reachable at 200% text scale (NFR6).
- Recent archives: each row announced as **"&lt;name&gt;, &lt;date&gt;, &lt;size&gt;"**.
- Error messages linked to relevant field where applicable (`Semantics` error property on source/destination fields).
- Colour contrast per app theme tokens — 4.5:1 minimum for status text.

## 13. Performance

| NFR | Applies | Target | Surface |
|-----|---------|--------|---------|
| NFR2 | Foreground scroll of recent archives list | ≤ 16 ms p99 frame time | Recent archives section |
| NFR6 | Backup screen at 200% text scale | Primary action visible without horizontal scroll | Full screen |
| NFR7 | Offline usability | 100% of flows in §4 without network | Integration tests |
